## 판단

**현재 구성에서 이 모델은 마피아의 역할 유지와 정보에 근거한 의사결정을 안정적으로 수행하지 못한다. 동시에 하네스가 잘못된 발언의 반복과 동조를 증폭하고 있다.** 따라서 “9B의 한계이므로 바로 imitation learning이 필요하다”까지 결론 내리기는 이르다.

이미 확인되는 모델 행동의 문제는 분명하다. 경찰이 받은 확정 조사 결과를 무시하고 다른 시민을 투표하거나, 마피아가 공개 토론에서 자기 동료 관계를 드러낸다. 역할 전달 자체가 빠졌거나 서버가 응답을 잘라서 생긴 현상으로 설명되지 않는다. 다만 역할을 매 턴 명확히 제시하는 입력 구성과 반복 토론 제어를 먼저 비교해야, 모델의 부족과 하네스의 부담을 분리할 수 있다.

권장 순서는 **역할·상태 입력 개선의 대조 실험 → 같은 조건의 더 강한 모델 대조 → 남는 오류에 대한 IL 판단**이다. thinking OFF 조건은 유지한다. 승률보다 역할·정보·행동의 일관성을 먼저 평가해야 한다.

## 모델 행동: 분명하게 나쁜 사례

### 1. 받은 정보를 기억하는 것과 행동에 쓰는 것이 분리된다

마피아 seed 3의 Player 1은 경찰이다. 첫날 밤 사회자에게 **Player 3은 마피아**라는 결과를 받았다. 낮에는 그 결과를 언급하면서도 “살아 있으니 의사의 보호였을 가능성이 높다”고 연결한다. 조사는 상대를 죽이는 능력이 아닌데 조사·공격·보호를 혼동했다. 이후 공개 토론은 Player 2와 Player 7의 침묵을 의심하는 내용으로 쏠렸다.

그날 경찰의 실제 투표는 **Player 2**, 즉 의사였다. 그 시점에 Player 3은 생존 중이었고, 실제 입력에는 경찰 자신의 역할과 Player 3의 확정 조사 결과가 모두 있었다. 해당 API call은 **250**, 입력은 **1,956토큰**이었다. 긴 문맥 한도에 걸려 정보가 사라진 사례가 아니다.

- [조사와 보호를 혼동한 발언](../../outputs/qwen35_pilot/job_268515/mafia/seed_3/conversation.txt#L145)
- [실제 투표](../../outputs/qwen35_pilot/job_268515/mafia/seed_3/conversation.txt#L196)

seed 1에서도 경찰 Player 6은 첫날 **Player 2가 마피아가 아님**을 확인했다. 그런데 둘째 날 반복된 의심에 합류해 Player 2에게 투표했다(API call **392**). 이 규칙에는 역할 변경이 없다. 확정된 비마피아를 마피아라고 취급하는 행동은 자신의 정보와 모순된다.

이 둘은 “다른 사람의 의심을 따라 하는 대화”가 “자신의 정보로 판단하는 에이전트”를 대체한 강한 증거다. 내부적으로 기억을 못 했는지, 기억했으나 판단에 반영하지 못했는지는 로그만으로 분리할 수 없다.

### 2. 자기 정체와 경쟁 목적을 유지하지 못한다

seed 1의 마피아 Player 1은 첫 공개 발언부터 **“Player 3과 Player 1의 공범 관계가 선명해졌습니다”**라고 말한다(API call **35**, 1,257토큰). 실제 입력은 자기 비밀 역할과 동료 Player 3을 정확히 포함했다.

동료 Player 3은 공개 토론에서 **“Player 3은 마피아로서 정체를 숨겨야 합니다”**라고 말한다(API call **214**). 정체를 숨기라는 지시를 행동으로 수행하는 대신, 지시 자체를 해설하는 형태다. 둘 다 단순히 역할 정보가 누락돼서 나온 응답은 아니다.

- [Player 1의 공개 발언](../../outputs/qwen35_pilot/job_268515/mafia/seed_1/conversation.txt#L118)
- [Player 3의 공개 발언](../../outputs/qwen35_pilot/job_268515/mafia/seed_1/conversation.txt#L184)

마피아 비공개 대화에서도 seed 2의 마피아들은 동료가 누구인지 알고 있으면서 공격 대상이 “마피아일 가능성이 높다”는 이유를 든다. 시민 역할의 목표와 마피아의 목표를 혼동하는 모습이다. seed 3에서는 시민 Player 4가 본인을 의심하는 주장을 반복하고 결국 자기에게 투표한다. 마피아 seed 1에서도 Player 3이 자기에게 투표했다. **마피아 하네스는 자기투표를 허용하므로 파싱 오류나 금지된 행동으로 셀 수는 없다.** 다만 전후 발언을 보면 안정적인 자기 관점의 증거로 보기 어렵다.

### 3. 문장은 이어지지만 사실·논리가 누적되지 않는다

seed 3에서는 “Player 1이 공격을 두 번 견뎠다”라는 잘못된 서사가 만들어지고, 이후 “Player 4가 두 번 견뎠다”로 대상이 바뀐다. 실제 밤 결과와 맞지 않는데 여러 플레이어가 반복한다. 같은 주장을 많이 들은 것이 새 증거처럼 작동한다.

seed 1에서는 시민과 의사까지 “오늘 밤 누군가를 제거하겠다”는 발언에 동조한다. 미래의 밤 전략을 말하는 것 자체를 모두 불법 행동으로 세지는 않았다. **실제로 낮에 공격이 실행된 것도 아니다.** 문제는 시민·의사가 자신에게 없는 공격 능력을 가진 것처럼 말하고, 자신의 확인된 사실과 역할에 반하는 전략을 따라간다는 점이다.

## 하네스: 무엇이 문제를 키우는가

### 1. 비밀 역할은 초반 user 메시지, 최신 지시는 일반 발언 요청이다

실제 API의 initial system에는 이름과 게임의 일반 규칙, 일반적인 role_desc가 있다. **마피아/경찰/의사/시민이라는 실제 역할은 초기 `[Moderator]` user 메시지에만 들어간다.** 마지막 speech 요청은 “현재 낮 토론, 짧게 응답, 밤 능력 사용 금지”를 말하지만 현재 발언자의 이름·역할·진영·공개 여부를 다시 제시하지 않는다.

다른 플레이어의 주장과 공식 결과도 모두 user role 메시지이며, 내용 앞의 `[Moderator]`/`[Player N]`으로 구분한다. 모델은 역할을 배정받지 못한 것이 아니라, 초반의 권위 있는 사실을 여러 사람의 최근 주장과 구분하고 매 턴 유지해야 하는 부담을 받는다.

이는 **관측된 입력 구조**다. 이것이 오류를 얼마나 유발했는지는 아직 대조 실험이 없어 가설이다. 다만 가장 먼저 고쳐 비교할 만하다. 최신 요청에 자기 이름·역할·진영·현재 단계·청중·생존자·실행 가능한 행동을 명확히 주고, 자기에게 알려진 공식 결과를 플레이어 주장과 분리해서 제공하는 방식이 적절하다. 남의 비밀 역할이나 비공개 결과를 요약에 넣으면 안 된다.

근거: [API 변환](../../chatarena/backends/openai.py#L94), [system 구성](../../chatarena/backends/openai.py#L193), [턴별 요청](../../chatarena/mafia_discussion.py#L145).

현재 “초기 system 하나 + 나머지 user/assistant” 구성은 Qwen 템플릿의 system 위치 제약을 만족하기 위해 사용됐다. 템플릿 거부 오류는 해결됐지만, 의미 전달까지 최적화됐다는 뜻은 아니다. system을 중간중간 다시 넣는 방식으로 되돌리면 이전 오류가 재발하므로, 단일 초기 system과 마지막 요청 안에서 상태를 명확히 해야 한다.

### 2. LLM moderator는 이번 실행에서 반복을 끝내지 못했다

| 마피아 | API 호출 | 의향 요청 | 발언 생성 요청 | 사회자 요청 | 실제 낮 공개 발언 |
| --- | ---: | ---: | ---: | ---: | ---: |
| seed 1 | 394 | 256 | 73 | 46 | 48 |
| seed 2 | 394 | 256 | 76 | 46 | 48 |
| seed 3 | 459 | 320 | 74 | 46 | 48 |
| 합계 | 1,247 | 832 | 223 | 138 | 144 |

사회자는 **138/138번 CONTINUE**, END_DISCUSSION은 0번이었다. 세 게임 모두 낮이 두 번 있었고, 여섯 낮 토론은 모두 24발언 한도에 도달했다. 24번째 발언 뒤에는 controller가 한도로 종료하므로 사회자 요청은 낮마다 23번이다. 마피아 비공개 토론에는 LLM moderator가 적용되지 않고 별도의 8발언 한도가 적용된다.

즉, “LLM moderator ON”은 켜져 있었지만 이번 실행에서 조기 종료 기능을 수행하지 못했다. 사회자 프롬프트가 여러 번 CONTINUE를 기본값으로 강조하며, 같은 사람을 의심하는 것만으로 끝내지 말라고 지시하는 점도 종료를 보수적으로 만든다. 모델의 반복 감지 능력과 프롬프트의 기본값 편향을 분리해서 평가해야 한다. 이 사회자는 종료 판단만 하도록 설계됐으므로 역할 오류를 교정하지 않는 것을 기능 고장으로 볼 수는 없다.

### 3. 의향 선택이 침묵·새 정보보다 발언 반복에 치우친다

832개 의향 응답 중 **824개(99.0%)가 2 또는 3**이었다. 0은 4개, 1은 4개뿐이다. 실제 발언 요청 223개 중 47개는 PASS였다. 의향 단계에서는 모두 적극적으로 말하겠다고 하고, 막상 선택되면 말을 하지 않는 불일치도 있다.

의향 점수는 가중 추첨이며, 연속 발언은 가중치 0.5를 곱할 뿐 금지하지 않는다. 질문을 받은 대상에게 다음 발언을 보장하는 방식도 아니다. seed 2 첫날 의사의 공개 발언은 2번에 그쳤지만, 이후 추가로 선택됐을 때 PASS를 냈으므로 이를 단순히 발언 기회를 못 받은 사례라고 해석하면 안 된다. 앞선 두 발언은 문장 뒤에 PASS를 붙였고 하네스는 일반 발언으로 받아들였다. 한편 seed 3 첫날 “Player 2와 Player 7이 너무 조용하다”는 주장은 둘 다 이미 발언한 뒤에 확산됐다. 실제 침묵과 모델의 주장을 구분해야 한다.

세 판의 실제 비공개+공개 토론 발언 176개 중 **완전히 같은 문장의 추가 반복만 35개(19.9%)**다. 의미는 같고 표현만 바뀐 반복은 이 수치에 포함하지 않았다. 동일 모델의 응답들이 서로의 최근 문장을 모방하는 경향과 반복을 허용하는 하네스가 함께 작용한다는 해석이 타당하다. 그 인과 효과의 크기는 아직 측정하지 않았다.

의향+사회자 요청이 마피아 API 호출의 **77.8%**다. 이것은 호출 수 비중이며 GPU 시간이나 비용 비중을 뜻하지 않는다. 현재 구조는 짧은 대화 한 문장을 위해 많은 제어 요청을 사용하면서, 그 요청들이 대화 품질을 충분히 개선하지 못했다.

### 4. 성공 판정과 학습 적합 판정이 너무 약하다

마피아 `valid`는 대부분 비어 있지 않은 응답·제어 형식·대상 인식에 대한 판정이다. 역할에 맞는 전략이나 사실 일관성을 검사하지 않는다. 그래서 의미적으로 나쁜 응답도 valid=true다.

특히 `trainable=true`는 **유효하고 stale/retry가 아니며 사회자 요청이 아니라는 조건**이다. 이번 실행에서 1,109건이 trainable이며, 앞서 인용한 공개 자기 역할 노출도 여기에 포함된다. “좋은 전문가 행동”이라는 라벨로 사용할 수 없다. 의향 응답 832개가 이 집합의 약 75%이므로 그대로 학습하면 숫자 출력 위주의 데이터가 된다.

또 `decisions.json`의 `request.prompt`는 진단용 조립 텍스트다. 실제 API의 전체 initial system과 같지 않다. 학습 입력은 원문 API 입력 또는 동일한 실제 입력 생성 경로를 기준으로 구성해야 한다. moderator는 현재 trainable에서 제외돼 있다는 점은 적절하다.

근거: [trainable 판정](../../chatarena/mafia_discussion.py#L361), [진단 prompt와 실제 요청 연결](../../chatarena/arena.py#L49).

## 라이어 게임은 따로 해석해야 한다

| seed | 단어 | 라이어 / 첫 발언 순서 | 비라이어의 올바른 투표 | 결과 |
| --- | --- | --- | --- | --- |
| 1 | Sunglasses | Player 4 / 네 번째 | 2/4 | 다른 사람 지목, 라이어 승 |
| 2 | Cloud | Player 3 / 세 번째 | 1/4 | 다른 사람 지목, 라이어 승 |
| 3 | Amusement Park | Player 5 / 다섯 번째 | 4/4 | 라이어 적발, 최종 추측 실패 |

라이어 게임은 두 차례 정해진 순서로 단서를 말하고 비공개 투표하는 구현이다. 자유 질의응답이나 심문 단계가 없다. 따라서 “에이전트끼리 자연스럽게 대화하며 추리하는가”를 이 실행으로 충분히 평가할 수 없다. 마피아는 한국어, 라이어는 영어이며 인원·복잡도도 다르므로 두 게임의 성능 차이를 모델의 언어 능력 차이로 단정할 수도 없다.

세 판 모두 라이어가 첫 발언 전에 2~4개의 단서를 들었다. 첫 번째나 두 번째로 말하는 조건은 평가되지 않았다. seed 1에서는 첫 두 단서가 “햇빛으로부터 눈을 가림”, “얼굴에 착용해 눈부심 차단”이다. seed 2는 “하늘에 모여 비를 가져옴”, “하늘 위 흰 수증기”다. 라이어가 잘 맞춰 말하는 것은 비밀 단어 전달 버그 없이도 충분히 설명된다. 비라이어가 단어를 너무 쉽게 유추하게 만드는 것이 전략적 약점이다.

seed 1의 라이어는 **“A small, flat rectangle often found in sunglasses”**라고 실제 정답을 직접 말했다. 이는 단어를 말하지 말라는 명시적 규칙에 어긋난다. 하지만 하네스는 clue의 금지어를 검사하거나 벌칙을 적용하지 않고 그대로 진행했다. 나중에는 그 라이어가 이겼다. 따라서 이 판의 승리 자체를 규칙을 잘 이해한 증거로 쓰면 안 된다. 비라이어 Player 3의 “Lend a hand to hold a beach ball”도 단어와 맞지 않는 단서여서, 비라이어를 의심하는 것이 무조건 불합리한 것은 아니다.

seed 3은 정답이 장소인데 최종 추측이 **roller coaster**였다. 이미 이전 단서에서 놀이공원의 전체 시설을 설명했지만 부분 시설을 답한 것이다. 현재 사례의 실패는 맞는 단어를 파서가 잘못 거절한 경우가 아니다.

라이어 판정 코드에는 추가로 주의할 점이 있다. 투표 파서는 정확한 문장 형식 대신 이름의 포함 여부를 보므로 부정문·여러 이름도 수용할 수 있다. 최종 정답은 제한된 문자열 정규화로 비교해 동의어를 인정하지 않는다. 동률은 정해진 플레이어 순서로 해결한다. **이번 세 판은 투표 형식이 모두 정확했고, 득표 동률도 없었으므로 이 파서·동률 규칙이 실제 승패를 바꾼 증거는 없다.** 규칙의 명시와 평가 지표를 정비할 대상이지, 이번 실패의 주원인으로 지목할 대상은 아니다.

## 모델 설정에서 남은 비교 변수

thinking OFF는 모델이 지원하는 공식 사용 방식이며, 현재 요청도 그 방식이다. Qwen 공식 모델 카드는 non-thinking 일반 작업에 temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5를 제안한다. 이번에는 플레이어 temperature=0.6, 사회자=0.3만 명시했고 top_p/top_k/presence_penalty는 보내지 않았다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices).

캐시에는 generation_config.json이 없고 config/text_config에도 sampling override가 없다. 설치된 vLLM 0.22.0 코드상 이러한 요청은 top_p=1.0, top_k=0(제한 없음), presence_penalty=0.0으로 해석된다. 이는 저장된 요청·캐시·설치 코드에서 확인한 설정 해석이며, 서버가 호출별 최종 SamplingParams를 별도로 저장한 것은 아니다.

공식 권장값과 달랐다는 사실만으로 역할 혼동을 설명할 수 없다. 반복 방지 값을 올리면 해결된다고 단정해서도 안 된다. 샘플링 변경은 독립된 비교 축으로 두고, 숫자/제어 토큰 출력과 자유 발언을 구분해야 한다. 공식 문서도 높은 presence penalty가 언어 혼합이나 성능 저하를 일으킬 수 있다고 설명한다. [공식 주의사항](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices).

게임 seed는 환경 무작위성을 제어하지만 API 요청에는 seed가 없다. 서버에는 전역 seed=0이 있으나 병렬 처리와 요청 순서까지 포함한 게임별 동일 샘플 재현을 보장하는 조건은 아니다. 각 게임 3판, 모든 인물이 동일 모델, thinking OFF만 평가했으므로 크기 자체의 한계나 IL의 효과를 인과적으로 판단할 수 없다.

추가로 Message.timestamp의 기본값이 클래스 정의 시 한 번 계산돼, 각 로그 안에서 timestamp가 전부 같다. 대화 저장 순서는 turn과 삽입 순서로 유지돼 이번 내용 혼동의 원인으로 보이지 않는다. 시간 분석에는 API started/elapsed를 써야 한다. [해당 코드](../../chatarena/message.py#L44).

## 다음에 무엇을 비교할까

대규모 게임을 더 돌리기 전에, 이미 발견한 실패 상황에서 작고 통제된 비교를 하는 것이 좋다. 실제 적용·실행은 이번 분석 범위에 포함하지 않았다.

1. **9B / thinking OFF를 유지하고 입력 구조만 비교한다.** 매 턴 자기 역할·진영·청중·현재 단계와 자기에게 알려진 공식 사실을 명확히 준다. 경찰이 확정 결과를 행동에 사용하는지, 마피아가 공개/비공개 전략을 구분하는지 먼저 본다. 공식 사실과 다른 사람 주장은 구분한다. 게임 정답을 몰래 보태는 방식은 금지한다.
2. **같은 게임 조건에서 더 강한 모델을 비교한다.** 역할·말 순서·단어·규칙·샘플링 조건을 맞춘다. 큰 모델도 같은 방식으로 무너지면 하네스 문제의 비중이 크다. 큰 모델은 안정적이고 개선된 9B만 계속 실패하면 모델 능력 부족의 근거가 강해진다.
3. **사회자와 반복 제어는 별도 비교한다.** 기존 로그의 반복 구간에서 END_DISCUSSION을 판단하는지 먼저 평가한다. 사회자를 강화하는 것과 플레이어를 강화하는 효과를 구분한다. 발언 기회 보장은 별도 하네스 변경으로 관리한다.
4. **라이어는 발언 위치를 균형 있게 평가한다.** 단어를 직접 말한 위반, 단서의 지나친 노출, 적발 정확도, 최종 추측을 별도 지표로 둔다. 자유 심문을 추가하면 다른 게임 규칙이 되므로 기존 결과와 섞지 않는다.

평가 지표는 우선 다음 여섯 가지면 충분하다: 역할/자기 정체 유지, 단계에 맞는 능력 이해, 공식 결과와 행동의 일관성, 비밀 정보 공개의 적절성, 근거 없는 주장·반복의 비율, 합법적인 대상 선택. 이 위에 게임별 전략과 승패를 얹는다. 경찰·의사의 역할 공개는 전략적으로 가능하므로 모든 비밀 역할 발언을 일괄 위반으로 분류하면 안 된다.

## Imitation learning에 대한 현재 결론

**IL이 도움이 될 법한 오류 유형은 확인됐지만, 필요성이 확정되지는 않았다.** 단순 형식은 이미 대체로 맞고, 문제는 역할별 목적·정보 신뢰도·자기 관점을 유지한 행동이다. 프롬프트를 명확히 해도 이 문제가 남는다면, 바로 그 유형이 IL의 목표가 된다.

학습한다면 역할별로 좋은 행동을 보이는 전문가 시연을 확보하고, 각 에이전트가 실제로 보았던 정보만 입력으로 사용해야 한다. 경찰은 알려진 결과와 일관된 판단, 마피아는 공개 발언과 동료 비공개 논의 구분, 비라이어는 적절한 단서 공개, 라이어는 관측한 단서로 추론하는 사례가 필요하다. 역할 배치·단어·발언 위치가 다른 평가를 따로 두어야 한다.

**현재 자기 생성 로그를 trainable 플래그만 보고 그대로 학습하는 것은 권하지 않는다.** 나쁜 전략·자기 노출·반복까지 모방하게 된다. 이 로그는 우선 실패 사례집과 하네스 개선 전 기준점으로 쓰는 것이 맞다. 승리한 게임에서도 경찰의 정보 무시나 마피아의 자기 팀 투표가 발생하므로, 승리한 궤적만 골라도 좋은 시연이 보장되지 않는다.
